# BRCA Methylation — Pipeline Builder (prototype)

A drag-and-drop UI that runs the BRCA methylation pipeline end to end: build the block
graph, tune every filter and parameter, hit **Run sample**, then read the results,
generate a report, and download every file the run produced.

This folder is **separate from the published project**. The published results site is
copied in verbatim and served read-only — the builder never writes to it.

---

## Run it

```bash
python server/app.py
```

Then open <http://127.0.0.1:8765/>. On Windows you can also just double-click
`start.bat`. Needs Python 3.9+ with `numpy`, `pandas`, `scipy`, `scikit-learn`
(all already installed on this machine).

---

## What the five tabs do

| Tab | What it is |
|---|---|
| **Builder** | The canvas. Drag blocks from the left palette (or click one to chain it onto the selected block), wire them up, and adjust parameters on the right. The run log streams underneath. |
| **Results** | Headline numbers, interactive volcano plot, ROC curve, direction-of-effect split, marker and panel tables. |
| **Report** | A self-contained HTML report generated by the run. Open it in a tab or download it. |
| **Downloads** | Every file the run wrote, individually or as one zip. |
| **Published site** | The original results website, served verbatim. Read-only. |

### Working on the canvas
- **Drag** a block from the palette onto the canvas, or **click** it to append it to the selected block and auto-connect.
- **Drag a block** by its body to move it.
- **Connect** blocks by dragging from the right-hand dot of one to the left-hand dot of another.
- **Click a connection** to delete it. **Click the ✕** on a block, or select it and press Delete, to remove it.
- **Reset graph** restores the published pipeline. **Export graph** saves the graph as JSON.

## The blocks

Every block maps to a step in `project_b/scripts/` in the published repo, and its
defaults are that step's published settings.

| Block | Does | Key parameters |
|---|---|---|
| Load dataset | Reads a beta matrix + sample manifest | dataset, custom paths, probe cap |
| QC filter | Drops high-missingness samples/probes, sex chromosomes | max sample/probe missingness, drop chrX/Y |
| Probe pre-filter | Optional unsupervised variance reduction | min variance, keep top-N variable |
| Differential test | Per-probe group comparison | comparison, subtype, Welch / Student / Mann-Whitney |
| Multiple-testing correction | Raw p → adjusted p | Benjamini-Hochberg / Bonferroni / none, threshold |
| Effect-size filter | Keeps biologically meaningful shifts | min \|Δβ\|, direction, min samples per group |
| Annotate sites | Gene, coordinate, region, CpG-island context | promoter window, island/shore restriction |
| Direction of effect | Promoter rule → silencing / activation / ambiguous | strict promoter only, treat shores as promoter-like |
| Biomarker panel | Ranked, de-duplicated marker set | panel size, rank by, balance directions, max per gene |
| Classifier + validation | Cross-validated tumour/normal model | model, features, folds, **nested selection**, seed |
| Pathway enrichment | Hypergeometric ORA vs real GMT libraries | libraries, background universe, set-size limits, FDR |
| Generate report | Standalone HTML report | title, which sections to include |

Two parameters are worth playing with because they change the *conclusion*, not just
the numbers:

- **Classifier → Nested feature selection.** ON re-picks features inside each training
  fold, so the test fold never influenced feature choice. Turn it OFF and the AUC rises
  — that rise is leakage, and the UI warns you about it.
- **Pathway enrichment → Background universe.** "Genes on the array" is correct. Switch
  to "Genes in the library" and terms light up for the wrong reason.

## About the sample data — read this

**The per-sample beta values in the bundled cohort are simulated.** The published
repository ships summary tables, not the raw 888 × 485,000 beta matrix, so a
self-contained demo cannot use real per-sample values.

What is **real**, taken from the published outputs:
- probe ids, gene symbols, chromosomes and coordinates for the 500 reference probes
- their measured tumour and normal mean beta values
- their within-group SD, back-solved from the published p-value, Δβ and group sizes
- region / CpG-island annotation for the 100 candidate-panel probes
- the KEGG / Reactome / GO / longevity GMT libraries

What is **simulated**: every individual sample value, the 2,400 `sim*` background
probes, sample identifiers, and the planted missing data. Three sample-level effects
are modelled so the cohort does not separate unrealistically cleanly — tumour purity,
adjacent-normal field effect, and a per-sample technical offset. Each models a
limitation the published caveats already call out.

The simulation is calibrated: across the 500 reference probes the observed Δβ
correlates with the published Δβ at **r = 0.996** with mean bias −0.003.

So: **the algorithms are the real ones; the numbers are a faithful reconstruction at
n=130 rather than n=888.** Every generated report says so on its front page.

Full detail: [`data/sample/PROVENANCE.md`](data/sample/PROVENANCE.md).
Regenerate with `python server/engine/make_sample_data.py` (fixed seed, reproducible).

### Running on real data
Set the **Load dataset** block's *Dataset* to `custom` and give it:
- *Matrix path* — TSV/TSV.GZ, probes in rows, samples in columns (e.g. `TCGA-BRCA.methylation450.tsv.gz`)
- *Manifest path* — TSV with `sample_barcode` and `sample_class` (`tumor`/`normal`) columns, optionally `subtype`

Everything else works unchanged. The differential test is vectorised, so ~485k probes
is fine.

## Layout

```
Methylation-UI/
  server/
    app.py                    stdlib HTTP server + JSON API
    engine/
      catalog.py              block definitions — palette and parameters come from here
      nodes.py                the actual pipeline implementations
      runner.py               topological graph executor
      report.py               standalone HTML report generator
      make_sample_data.py     builds the bundled sample cohort
  web/
    index.html, builder.css, builder.js
    site/                     the published site, copied verbatim — do not edit
  data/
    sample/                   bundled cohort + GMT libraries + PROVENANCE.md
    reference/                published summary tables the sample cohort is calibrated to
  runs/                       one folder per run (auto-pruned to the newest 25)
```

## API

| Endpoint | Purpose |
|---|---|
| `GET /api/catalog` | Block definitions + default graph |
| `POST /api/run` | `{graph}` → `{run_id}` |
| `GET /api/runs/<id>?since=N` | Status, incremental logs, results |
| `GET /api/runs/<id>/file?path=…` | One output file |
| `GET /api/runs/<id>/download` | Everything as a zip |

## Prototype limits
- Runs are held in memory, so restarting the server forgets them (the files stay on disk).
- Single process, intended for local use — no auth, bound to `127.0.0.1`.
- Mann-Whitney is a per-probe Python loop; it is slow on a full 485k-probe matrix. Welch and Student are vectorised.
